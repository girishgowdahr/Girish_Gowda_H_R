# Change Report: Phase 1, Task 1.2 — Spring Boot Backend Skeleton

**Date:** 2026-11-12  
**Task:** Phase 1, Task 1.2 — Spring Boot backend skeleton  
**Status:** Completed  

---

### Objective
Create the Spring Boot backend skeleton conforming to the modular monolith architecture outlined in `03_PROJECT_STRUCTURE.md`. Verify runtime environment versions, implement Actuator health endpoints, configure RFC 9457 `application/problem+json` exception handling, configure OpenAPI 3 specifications, set up baseline Spring Security with application hardening headers, implement ArchUnit boundary test skeleton, and provide automated unit and integration tests.

### Key Decisions (and why)
1. **Java & Framework Version Choice:** Selected Java 21 LTS (matching local OpenJDK 21.0.12) and Spring Boot 3.4.3. Documented in ADR 0002.
2. **RFC 9457 Problem Details:** Configured `application/problem+json` as standard error representation to ensure zero stack trace leaks in production.
3. **Defense-in-Depth Security Headers:** Pre-configured `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, and `Permissions-Policy`.
4. **Architectural Guardrails via ArchUnit:** Implemented ArchUnit test suite to prevent cyclic dependencies and prevent `common` from referencing business domain modules.

### Security Implications
- Protected areas configured: `com.girish.config.SecurityConfig` and `com.girish.config.CorsConfig`.
- Default deny-by-default rule: any endpoint not explicitly permitted requires authentication.
- CSRF protection enabled.
- Stack traces and internal exception messages suppressed on error responses.
