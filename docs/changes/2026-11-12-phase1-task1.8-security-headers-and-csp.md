**Date:** 2026-11-12  
**Task:** Phase 1, Task 1.8 — Security headers & CSP baseline

---

### Objective
Implement a hardened, defence-in-depth security header and Content Security Policy (CSP) baseline across both the Spring Boot backend and Vite/React frontend. Ensure compliance with modern browser isolation standards (HSTS preload, strict CSP denying third-party scripts and object embeds, Cross-Origin-Opener-Policy, Cross-Origin-Resource-Policy, Permissions-Policy, X-Frame-Options DENY, and X-Content-Type-Options nosniff).

---

### Protected Area Review Notice
- **Application Security Hardening:** Verified that the Content Security Policy explicitly disallows plugin objects (`object-src 'none'`), disallows iframe clickjacking (`frame-ancestors 'none'`), restricts style and image origins, and sets strict boundaries for API connections (`connect-src 'self' http://localhost:5173 http://localhost:8080`).
- **Cryptographic Isolation:** Added `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Resource-Policy: same-origin` to prepare for high-precision WebAssembly and libsodium crypto worker memory isolation in Phase 6 (Vault).

---

### Key Decisions (and why)
1. **Defense-in-Depth Edge & App Alignment:** Enforced consistent security headers in Spring Boot backend, Vite dev server, and frontend `index.html` so that headers are active during both development and production.
2. **Future-Proof Header Writers:** Migrated Permissions-Policy and Cross-Origin isolation headers to Spring Security's `StaticHeadersWriter` to prevent deprecation issues in Spring Security 6.4+.
3. **Wasm & Worker Preparation:** Set `Cross-Origin-Opener-Policy: same-origin` to provide origin isolation required by future cryptographic Web Workers (libsodium / Argon2id).
