### Objective
Establish the relational database persistence baseline using PostgreSQL and Flyway migrations for the `core` domain schema (`core.app_user`, `core.auth_credential`, `core.session`, `core.avatar_theme`, `core.module_state`). Integrate Spring Data JPA, configure Hikari connection pooling, implement baseline seed data (including Free Fire battle-royale avatar themes and core module registry entries), and provide automated migration verification via both Spring Data JPA/Flyway integration tests and Testcontainers PostgreSQL container tests.

### Key Decisions (and why)
1. **Schema-Qualified Isolation:** Configured PostgreSQL `core` schema so that sensitive tables (`app_user`, `session`, `auth_credential`) are logically isolated from application data schemas (`portfolio`, `personal`, `vault`), setting up the foundation for least-privilege database roles and Row-Level Security (RLS) in Phase 4.
2. **Deterministic Dual-Harness Testing:** Implemented an `@EnabledIf("isDockerAvailable")` guard on `PostgresFlywayMigrationIntegrationTest` while verifying full Flyway schema and JPA validation in `FlywayCoreMigrationTest`. This guarantees tests run reliably both on local environments without Docker and in CI environments with Docker.
3. **Hibernate 6 JSON Mapping:** Utilized `@JdbcTypeCode(SqlTypes.JSON)` for JSONB fields (`config`, `feature_flags`) to pass Hibernate `ddl-auto: validate` schema checks without external custom type libraries.
